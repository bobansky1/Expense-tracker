# Размещение «Траты» на Beget

Подготовлено для обычного виртуального хостинга Beget: PHP 8.2+ с PDO MySQL и mbstring, MySQL 5.7+ или MariaDB 10.4+, HTTPS. Node.js нужен только на компьютере для сборки сайта. Приложение размещается в корне домена, а не в подпапке.

## 1. Сохраните старые расходы

В старой версии приложения скачайте «Копия JSON». Новый домен не видит хранилище старого адреса. Если адрес и браузер остаются прежними, после входа появится кнопка переноса. Автоматически старые записи не удаляются и не отправляются.

## 2. Создайте сайт и базу в панели Beget

1. В разделе «Сайты» создайте сайт, привяжите домен. Выберите PHP 8.2 или новее.
2. Подключите SSL-сертификат и включите перенаправление HTTP → HTTPS. Используйте один основной адрес: с www или без.
3. В разделе MySQL создайте отдельную пустую базу и задайте сложный пароль. Запишите точные имя базы, имя пользователя и адрес сервера из панели.
4. Откройте phpMyAdmin, выберите эту базу → «Импорт» → загрузите `mysql-schema.sql` из подготовленного пакета.

SQL создаёт пять таблиц: users, expenses, categories, app_meta, login_attempts. Это структура без личных расходов. Импортируйте её один раз в ПУСТУЮ базу. Если раньше импортировали старую заготовку, создайте новую базу: существующие таблицы и данные скрипт намеренно не удаляет.

## 3. Соберите пакет на компьютере

В папке проекта:

```sh
npm ci
npm run package:beget
```

Команда создаст новую папку `release/beget-ДАТА/`. Её путь также записан в `release/LATEST.txt`.

Загрузите файлы через файловый менеджер Beget или SFTP так:

```text
папка-сайта/
├── private/
│   ├── app.php
│   ├── validation.php
│   ├── config.example.php
│   └── config.php          ← создаётся вами
└── public_html/
    ├── index.html
    ├── .htaccess
    ├── assets/
    └── api/
        └── index.php
```

В `public_html` должно попасть СОДЕРЖИМОЕ одноимённой папки пакета. Папка `private` лежит рядом с `public_html`, на уровень выше публичных файлов. SQL и инструкцию на сайт загружать не нужно. Исходники, node_modules, .git и пароли тоже не загружаются в public_html.

## 4. Настройте подключение

В `private` скопируйте `config.example.php` в `config.php`. Заполните:

- `origin`: точный адрес сайта, например `https://budget.example.ru`, без пути и завершающего слеша;
- `db_host`, `db_port`, `db_name`, `db_user`, `db_password`: значения из панели Beget;
- `secure_cookies`: оставьте `true`;
- `setup_token`: случайный код первичной настройки, минимум 32 символа.

Создать код можно на своём компьютере командой:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Этот код не является паролем MySQL. Не отправляйте файл config.php в GitHub и не размещайте его внутри public_html. Для паролей с одинарной кавычкой или обратным слешем соблюдайте экранирование строк PHP.

Папка private должна быть доступна PHP для записи: приложение создаст в ней каталог sessions. Используйте права только для вашего пользователя хостинга; не ставьте 777.

## 5. Создайте аккаунт и перенесите записи

1. Откройте сайт по HTTPS.
2. Введите свой email, новый пароль (от 12 символов, максимум 72 байта) и код setup_token.
3. Нажмите «Создать мой аккаунт». После создания повторная регистрация закрывается.
4. Удалите значение setup_token из config.php или замените его пустой строкой: для обычного входа он больше не нужен.
5. Войдите → «Восстановить» → выберите старый JSON → скачайте текущую копию, если она нужна → подтвердите замену.
6. Если появились старые записи браузера, можно вместо JSON нажать «Перенести»: одинаковые ID не дублируются; при различающихся данных с одинаковым ID операция отменяется полностью.
7. Добавьте тестовый расход и проверьте его с телефона, войдя в тот же аккаунт.

При работе с нескольких устройств нажимайте «Обновить». Если кто-то уже изменил данные, старое окно не перезапишет их молча: сначала потребуется обновить список.

## Обновления и резервные копии

- Перед обновлением скачивайте JSON и делайте резервную копию базы через панель Beget/phpMyAdmin.
- Заменяйте файлы public_html и код private/app.php, private/validation.php из нового пакета.
- Сохраняйте private/config.php и private/sessions. SQL при обычном обновлении повторно не импортируйте.
- JSON содержит расходы и свои категории; SQL-экспорт базы также содержит аккаунт и хеш пароля. Храните резервные копии приватно.
- Восстановление JSON заменяет все расходы текущего аккаунта в одной транзакции.
- Доступа без интернета нет: приложение показывает ошибку, если не получило подтверждение сервера.

## Если что-то не работает

- «Сервер ещё не настроен»: проверьте private/config.php и расположение папок.
- «Сервер временно недоступен»: проверьте реквизиты MySQL, импорт всех таблиц, модули pdo_mysql и mbstring. В PHP-журнал пишется только класс и код ошибки, без паролей и SQL-параметров.
- «Проверка безопасности»: откройте сайт строго по адресу origin, обновите страницу; убедитесь, что HTTPS включён.
- «Слишком много попыток входа»: подождите 15 минут.
- Большой JSON не загружается: PHP memory_limit рекомендуется 256M, max_execution_time 120; лимит приложения — 25 МБ и 100 000 расходов. Проверьте ограничения веб-сервера и тарифа.
- Письма для восстановления пароля пока не подключены. Сохраните пароль в менеджере паролей; для сброса используйте локальную/SSH-команду ниже.

## Сброс пароля владельца

Через SSH на хостинге запустите `php private/reset-password.php email@example.ru`, если загрузили этот служебный скрипт из server. Скрипт работает только из командной строки, запрашивает пароль и удаляет серверные сеансы. Не размещайте его в public_html.

## Обновление для своих категорий

Для уже работающего сайта перед заменой PHP и интерфейса выполните в phpMyAdmin `migrate-categories.sql` из нового пакета. Он добавляет таблицу категорий и расширяет поле категории в расходах, сохраняя существующие записи. Сначала сделайте резервную копию базы. Для новой базы используйте только `mysql-schema.sql` — изменения уже включены.

JSON версии 2 содержит расходы и свои категории. Старые копии со стандартными категориями также поддерживаются. При восстановлении расходы заменяются, категории из копии добавляются к существующим; конфликт ID или названия отменяет операцию целиком.
